# Compatibility and scope

The source of truth for this binding is the C ABI generated by upstream Stampeded.

| Component | Current baseline |
| --- | --- |
| Upstream repository | https://github.com/seuros/stampeded |
| Published C ABI | `stampeded-ffi` `0.4.1` |
| Published Rust core | `stampeded` `0.4.1` |
| .NET target | `net10.0` |
| Database | PostgreSQL 18+ with upstream schema version 5 |

The C ABI version is distinct from this binding's NuGet version.
See `native/upstream.json` for the published FFI pin and `native/Cargo.lock` for its resolved dependencies.
The C header is staged from the published crate; no Rust source is retained locally.
No engine code has been translated into C#.

## Public API coverage

| Capability | Current binding |
| --- | --- |
| Native version and stderr logging | Rust C ABI |
| Enqueue | Queue, task, JSON-object args, metadata, priority, max attempts, schedule time, unique key |
| Pull | Queue selection/exclusions, concurrency, batch size, poll and heartbeat intervals |
| Job snapshot | Copied from Rust's full job JSON into a managed typed snapshot |
| Outcomes | Complete, fail/backoff or explicit retry delay, requeue, timeout, discard |
| Resume state | Rust lease checkpoints |
| Named steps | Rust step load, completed/value/cursor lookup, completion, cursor writes and JSON |
| .NET hosting | DI registration, typed scoped handlers, bounded consumer threads, cooperative cancellation |
| Native transaction sharing | Not exposed by the C ABI; unavailable in this binding |
| Queue creation and arbitrary job queries | Not exposed by this wrapper; use upstream administration/SQL |
| Cron checking and lifecycle metadata | Present upstream, not yet wrapped in the public C# API |
| Scheduler, maintenance, dashboard, MCP | Separate upstream daemon, not part of the .NET package |

Some core Rust settings, including tenant-limit configuration and other worker features, are not
exported by the published C ABI. The binding preserves the exported Puller's behavior; it does not
claim parity with every setting of Rust's in-process Worker. New features should first be checked
against the upstream header, and missing exports discussed upstream rather than recreated in SQL.

## Native platforms

The earlier 0.4.0 baseline was built and tested on Linux x64. Windows x64 and macOS
ARM64 passed CI on an earlier baseline; the 0.4.1 build and TLS provider still need those native jobs
to run again. See [the validation record](validation.md) for tested revisions. Only 64-bit runtime
assets are currently built.
The build script also maps Linux ARM64, Windows ARM64 and macOS x64 to their Rust targets for future
validation. Those mappings alone do not establish support. Linux builds use glibc; Alpine/musl,
NativeAOT, trimming, cross-runtime deployment and performance under load have not been validated.

A NuGet package includes only the platform assets built before packing. The local package contains
Linux x64. CI combines the assets from its platform jobs; no publishing is configured.

## Database and upgrade boundaries

Npgsql is used only by the test harness for setup and assertions. Neither shipped package depends
on it. Queue operations go through the upstream C ABI and its connection pool, which cannot join
an existing Npgsql or EF Core transaction.

The SQL migrations come from the resolved published core crate. The build stages them and generates
`artifacts/native-source/schema.sql` for fresh installs with a matching migration ledger.
Review FFI release updates and rerun the ABI/database tests. Published NuGet packages must be
rebuilt to receive them.

The 0.4.1 C header exports the same signatures used by P/Invoke. The FFI crate selects
`tls-aws-lc` by default. Fresh schema installs record version 5. Existing databases must be upgraded
with the matching upstream daemon's `--migrate`; the C ABI does not export the migration function
and `StampededClient.Connect` does not install or upgrade a database.

The [upstream review](upstream-0.4-review.md) records a reproduced deduplication edge case and
its rollback-only SQL reproducer. Upgrading does not resolve that pre-existing upstream behavior.
